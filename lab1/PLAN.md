# План ЛР1 «Спецификация и архитектурное проектирование многоагентной системы»

## Что требует задание
1. Выбор и описание прикладной задачи.
2. Формальное описание МАС: агенты, роли, цели, знания, состояния, действия, полномочия, средства,
   каналы связи, правила взаимодействия и прочее.
3. Диаграмма ролей и граф коммуникаций.
4. Обоснование выбора архитектуры МАС.
5. Система должна подходить для ЛР2 (распределение задач), ЛР3 (переговоры, конфликты), ЛР4 (диверсии).

Отчёт в свободной форме, без исходного кода и демонстрационных материалов (они в приложениях, ссылками).

## Выбранная задача
Городская доставка заказов («последняя миля») группой автономных курьеров-роботов разных типов с общей
ограниченной зарядной инфраструктурой. Ядро реализовано в `lab1/mas` (см. `lab1/README.md`).

## Шаги
1. **Изучить ядро** (`lab1/mas/*`, `lab1/README.md`) — отчёт должен точно соответствовать реализации.
2. **Скрипт рисунков** `lab1/docs/make_figures.py` (matplotlib, без graphviz) → `lab1/figures/*.png`:
   - диаграмма ролей (роли, их цели/обязанности, связи «назначает», «обслуживает», «уведомляет»; строится из `roles.ROLES`);
   - граф коммуникаций по проекту (узлы — роли, рёбра — протоколы и перформативы из `roles.PERMISSIONS`);
   - наблюдаемый граф коммуникаций по трассе базового прогона (вес ребра = число сообщений, `metrics.msgs_by_edge`
     или трасса), с разбивкой по протоколам;
   - диаграмма состояний курьера (idle, to_pickup, to_dropoff, to_station, waiting_charge, charging, stranded, переходы с условиями);
   - жизненный цикл заказа в книге диспетчера (pending, announced, assigning, assigned, picked, delivered; release);
   - диаграммы последовательности: «заказ → назначение → забор → доставка → уведомление»; «зарядка»;
     «телеметрия и сторожевой таймер (потеря курьера → переназначение)»;
   - схема архитектуры (среда/физика, агенты, шина сообщений, подключаемые механизмы и реестр режимов, CLI/веб).
3. **Базовый прогон** для иллюстрации: несколько seed, таблица показателей (`lab1/results/baseline.csv`),
   чтобы показать, что система работает, и задать точку отсчёта для ЛР2–ЛР4.
4. **Отчёт** `lab1/report.md` → `lab1/report.docx` (через `lab1/tools/md2docx.py`).

## Структура отчёта
1. Введение: цель, краткое описание результата.
2. Прикладная задача: содержательное описание, почему именно МАС (распределённость, автономность, локальная
   информация, масштабируемость, устойчивость); формальная постановка (множества, параметры, ограничения,
   критерии: доля доставок в срок, время доставки, энергия, стоимость координации); допущения модели.
3. Формальное описание МАС как кортежа (агенты, среда, роли, протоколы, организация):
   для каждой роли — цели, знания (убеждения), состояния, действия, полномочия, средства, каналы связи
   (можно в стиле схем ролей Gaia: обязанности liveness/safety, разрешения, протоколы).
   Среда (наблюдаемость, детерминизм, дискретность), модель сообщений (поля, перформативы, задержка),
   протоколы и правила взаимодействия (пред- и постусловия, тайм-ауты, отказ, отзыв), организационная
   структура (иерархия диспетчер–курьеры, рыночные и одноранговые отношения для ЛР2–ЛР3).
4. Диаграмма ролей и её пояснение.
5. Граф коммуникаций: проектный и наблюдаемый; объём и структура трафика базового режима.
6. Диаграммы состояний и сценарии взаимодействия (последовательности).
7. Обоснование архитектуры: сравнение альтернатив (полностью централизованный оптимизатор, реактивный рой,
   чисто делиберативные BDI-агенты, LLM-агенты, гибрид) по критериям; выбранная гибридная архитектура
   (реактивный слой безопасности по батарее + делиберативный слой оценки заказов и зарядки + подключаемый
   слой координации); почему дискретно-событийная симуляция и без готовых фреймворков (явная логика —
   требование курса); как архитектура обеспечивает ЛР2 (сменные механизмы распределения), ЛР3 (дефицитный
   ресурс — места зарядки и лимит мощности), ЛР4 (явные сообщения, полномочия, истинный отправитель, трасса).
8. Программная реализация: модули, точки расширения, режимы демонстрации (CLI, веб) — без листингов кода.
9. Пример работы базового режима: таблица показателей, наблюдения.
10. Выводы.
Приложения: ссылки на исходный код и демонстрацию (заглушка `<ссылка на репозиторий>`), инструкция запуска.
