# ЛР4. Диверсионный анализ и оценка надёжности МАС

Неблагоприятные сценарии и защитные механизмы для МАС «Городская доставка автономными курьерами» (ядро — `lab1/`).
Ядро не изменялось: сценарии внедряются заменой агентов на подклассы (`replace_agent`), добавлением агентов,
промежуточными обработчиками шины и хуками такта; защиты — обработчиками шины и плагинами-фильтрами агентов.
Режимы регистрируются в `lab4/plugin.py` (категории `scenario` и `defense`) и видны в `lab1/run.py` и веб-демо.

Все команды — из корня репозитория.

```
python lab4/experiments.py                 # все эксперименты, ~2–3 мин -> lab4/results, lab4/figures, lab4/traces
python lab4/experiments.py --seeds 5       # быстрый прогон
python lab4/analyze.py lab4/traces/*.jsonl                       # отказы по каждой трассе
python lab4/analyze.py lab4/traces/rogue_courier__none.jsonl --examples 5
python lab1/run.py --scenario forged_authority --defense none --seed 2
python lab1/run.py --scenario forged_authority --defense full --seed 2 --trace t.jsonl
python lab1/web/server.py --port 8000      # веб-демо: выбрать «Сценарий (ЛР4)» и «Защита (ЛР4)»
python lab1/tools/md2docx.py lab4/report.md lab4/report.docx
```

## Сценарии (`--scenario`)

| Ключ | Что моделирует | Как внедряется |
|---|---|---|
| `false_telemetry` | недостоверные сообщения: courier-3 сообщает, что свободен, стоит на точке выдачи и полностью заряжен; «доставлено» шлёт сразу после забора | подкласс курьера `LiarCourier` |
| `rogue_courier` | агент с подменённой целью: courier-3 соглашается на все заказы, не возит их и скрывает очередь | `RogueCourier` |
| `station_outage` | недоступность внешнего средства: station-1 молчит с 50 по 350 такт; 5% сообщений теряется в канале | хук такта + обработчик шины |
| `forged_authority` | некорректная передача полномочий: courier-3 от имени диспетчера отзывает чужие заказы и раздаёт поддельные | `ForgerCourier` + пассивное подслушивание канала |
| `task_cycling` | циклическая передача задачи: courier-3 и courier-7 принимают заказ и через 3 такта возвращают | `CyclerCourier` |
| `contradictory` | противоречивые указания: реплика `dispatcher-b` (split-brain) отзывает и переназначает заказы основного диспетчера | агент `ReplicaDispatcher` + репликация журнала |
| `injection` | внедрение инструкций: каждый 5-й заказ несёт команду в заметке или в поле `priority`; наивный «понимающий» помощник диспетчера (модель LLM-подобного обработчика, часть сценария) её исполняет | плагин диспетчера `NoteAssistant` |
| `replay_flood` | повтор перехваченных сообщений через 15–60 тактов (10%) и лавины дубликатов (3% × 4) | обработчик шины (сетевой злоумышленник) |

Параметры сценариев — в `SimConfig.params` с префиксом `lab4_` (см. `lab4/scenarios.py`).

## Защиты (`--defense`)

| Ключ | Слой |
|---|---|
| `auth` | аутентификация: шина сверяет заявленного отправителя с истинным `origin` (модель подписи) |
| `authz` | авторизация по `roles.PERMISSIONS` (протоколы, не объявленные ни в одной строке таблицы, пропускаются); команды роли «диспетчер» — только от диспетчера получателя; действия, извлечённые из текста заказа, — в пределах полномочий автора заказа |
| `validate` | схема и диапазоны полей, нейтрализация инструкций в заметках (сигнатуры), правдоподобие телеметрии (скорость, расход энергии) и статусов (минимальное время доставки) |
| `fresh` | одноразовый номер и метка времени у каждого сообщения, отбрасывание повторов и устаревших, эпохи назначений (отзыв принимается только с эпохой своего назначения) |
| `monitor` | сверка книги заказов с телеметрией, тайм-аут исполнения, лимит передач (TTL) с исключением вернувших, «парковка» заказа, если посылки нет на месте, бета-репутация и карантин |
| `fallback` | станция не отвечает / не заряжает / долгая очередь — другая станция; клиент повторяет неподтверждённый заказ |
| `full` | все слои |

Параметры защит — `SimConfig.params` с префиксом `def_` (см. `DEFAULTS` в `lab4/defenses.py`).

## Файлы

- `plugin.py` — `register()`; `scenarios.py`, `defenses.py`, `common.py` (разметка атак для учёта, счётчики,
  наблюдатель ложных подтверждений, зонд истинного состояния для трасс).
- `analyze.py` — выявление отказов по трассе (таксономия F1–F13, причины недоставки, примеры строк).
- `experiments.py` — E1: матрица 9 сценариев × 8 защит × 25 seed; E2: показательные трассы (seed=2) и их анализ.
- `results/` — `runs.csv` (все прогоны), `summary.csv`, `resilience.csv`, `layers_on_time.csv`,
  `layers_completion.csv`, `false_positives.csv`, `detection.csv`, `trace_failures.csv`, `trace_examples.json`.
- `figures/` — `before_after.png`, `layers_heatmap.png`, `timeline.png`, `overhead.png`.
- `traces/<сценарий>__<защита>.jsonl` — трассы с сообщениями (с истинным `origin`), событиями агентов и защиты,
  снимками истинного состояния курьеров каждые 5 тактов (`truth`).
- `report.md`, `report.docx` — отчёт.

Дополнительные показатели в итогах прогона: `atk_*` — воздействия сценария (истинная разметка, только для учёта),
`def_*` — срабатывания защиты (`def_tp`/`def_fp` — отброшенные вредоносные/легитимные сообщения),
`false_confirm` — заказы, о доставке которых клиенту сообщили раньше факта или без доставки, `undelivered`.
