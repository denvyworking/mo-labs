# ЛР2. Механизмы распределения задач и координации

Плагин к ядру `lab1/mas` (см. `lab1/README.md`). Ядро не изменялось: механизмы подключаются через
`lab2/plugin.py` (`register()`), который регистрирует режимы категории `allocation` и новые протоколы
в таблице полномочий (`roles.allow`). Все команды — из корня репозитория.

## Режимы (`allocation`)

| Ключ | Механизм | Протокол | Модуль |
|---|---|---|---|
| `central` | Централизованная диспетчеризация (базовый, из ядра) | `assign` | `lab1/mas/allocation.py` |
| `cnp` | Контрактная сеть: CFP → PROPOSE/REFUSE → ACCEPT/REJECT → INFORM/FAILURE, перепроверка победителя | `cnp` | `lab2/cnp.py` |
| `cnp-commit` | Контрактная сеть с предварительными обязательствами в ставках | `cnp` | `lab2/cnp.py` |
| `auction` | Последовательный аукцион по одному лоту (SSI) по пакету заказов, плата по второй цене (Викри) | `auction` | `lab2/auction.py` |
| `auction-par` | Параллельный одноразовый аукцион по пакету заказов | `auction` | `lab2/auction.py` |
| `delegation` | Распределённое делегирование: перегруженный курьер сам передаёт заказ соседу | `assign`, `delegate` | `lab2/delegation.py` |

Каждый механизм состоит из плагина диспетчера (менеджер / аукционист / маршрутизатор) и плагина курьера
(участник торгов / партнёр по делегированию); вся координация идёт сообщениями шины. Подробное описание
правил — в строках документации модулей и в отчёте.

Параметры механизмов задаются через `SimConfig.params` (значения по умолчанию в скобках):
`cnp_slack` (1), `cnp_retry` (10), `cnp_commit`; `auction_period` (5), `auction_max_lots` (6),
`auction_slack` (1), `auction_retry` (10); `deleg_queue_limit` (2), `deleg_attempts` (3), `deleg_max_hops` (2),
`deleg_gain` (2), `deleg_cooldown` (15).

## Демонстрация

```
python lab1/run.py --list                                  # режимы lab2 видны в категории allocation
python lab1/run.py --allocation cnp --seed 2               # один прогон, таблица показателей
python lab1/run.py --allocation auction --trace t.jsonl    # трасса со всеми сообщениями (CFP, PROPOSE, ...)
python lab1/web/server.py --port 8000                      # веб-демо: выбрать режим в «Распределение заказов (ЛР2)»
```

## Эксперименты

```
python lab2/experiments.py                # E1–E5 и D1, 30 seed, ~2,5 мин (последовательно)
python lab2/experiments.py --jobs 8       # параллельно (~0,5 мин), но замеры CPU менее точны
python lab2/experiments.py --only E1 --seeds 5
```

* E1 — базовая конфигурация (8 курьеров, 60 заказов, 0,2 заказа/такт);
* E2 — масштабируемость: 4, 8, 12, 16, 24 курьера, поток и число заказов пропорциональны;
* E3 — интенсивность заказов 0,1 / 0,2 / 0,4 / 0,8;
* E4 — задержка сообщений 1 / 2 / 4 такта;
* E5 — период телеметрии 5 / 10 / 20 тактов;
* D1 — диагностика: доля назначений курьерам, которые едут на зарядку или заряжаются (24 курьера).

Для всех механизмов используются одни и те же seed (одинаковый поток заказов).
Результаты: `lab2/results/eN_*.csv` (строка = механизм × seed), `eN_*_summary.csv` (среднее, СКО, 95% ДИ),
`e1_paired_vs_central.csv` (парные разности с `central`), `d1_charging_assignments.csv`.
Графики: `lab2/figures/*.png`. Отчёт: `lab2/report.md` → `lab2/report.docx`
(`python lab1/tools/md2docx.py lab2/report.md lab2/report.docx`).
